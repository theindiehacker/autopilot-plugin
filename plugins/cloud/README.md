# ☁️ cloud

Claude Code on the Web のセッションを準備するプラグインです。PC には入れません。

## ⚙️ 自動で動くもの

| タイミング | 処理 | 動く条件 |
|---|---|---|
| 起動時 | `dockerd --registry-mirror=https://mirror.gcr.io` | 常に |
| 起動時 | `mise install` | Web で、`mise.toml` がある |
| 起動時 | `docker compose up --build -d --wait` (プロキシの CA をビルドと起動後のコンテナに渡す) | Web で、compose ファイルがある |
| 起動時・再開時・要約の後 | 下の「Claude に渡す指示」を渡す | Web のみ |

## 📝 Claude に渡す指示

- 自分の作った PR を `claude[bot]` のレビューが下書きに戻したときは、指摘を直す (または返信する) push をして CI が通ったら、ユーザーに聞かずに「レビュー可能」に戻してよい
- ほかの人が下書きに戻した PR は戻さない

Claude は、自分以外が下書きに戻した PR を、ユーザーに頼まれない限り「レビュー可能」に戻しません。この指示で、bot が戻した場合だけ Claude が戻せるようにします。

## 🚀 Docker で動くようにする

`/cloud:setup` を実行すると、起動時の処理を動かして失敗を集め、リポジトリを調べ、足りない項目ごとに確認しながら、クラウドで Docker を起動できるように直します。ローカルの Docker でも今までどおり動く形にします。

| 項目 | 内容 |
|---|---|
| compose ファイル | ルートに無ければ、サブフォルダのものを読み込むか、DB などの依存サービスだけで作る |
| プロキシの CA | Dockerfile の通信する `RUN` で、プロキシの CA を読む |
| `.env` | 無くても起動できるようにする |
| Mac 専用の設定 | `platform: linux/arm64` や、リポジトリの外のパスの mount を直す |
| 終了するサービス | migration などで起動の確認が止まらないようにする |
| 遮断されたドメイン | 一覧にして、環境の「許可されたドメイン」への追加を頼む |

最後に、起動時と同じ `docker compose up --build -d --wait` が通り、サービスに繋がることを確かめます。PR を作るかを聞き、作ると答えたら PR を作ります。
